## 2. الأرقام (r8 8.5.35، مكتبة android-30، JVM خالص بلا SDK)

- **التقليص**: dex ‏553,980 ← 420,236 بايت (**−24%**)؛ جرة البرنامج (باختباراته) 116K ← 104K.
- **التشويش**: 166 صنفاً في mapping — `Dictionary → a.C0`، `ClipRepo → a.n0`، `KeyboardView → a.S0`… بينما `NeoKeyService/SetupActivity/…` تبقى بأسمائها (شرط عمل النظام).
- **التشخيص**: أرقام الأسطر محفوظة للرمزيّة مع mapping، وأسماء الملفات الحقيقية مقنّعة (`-renamesourcefileattribute`) — تقرير عطل المستخدم يبقى قابلاً للفهم بعد التشويش.
- **أدوات بلا SDK**: r8.jar من Google Maven (16MB) + android.jar من مرايا Sable (21MB) — قابل للتكرار على أي جهاز.

## 3. الإثبات السلوكي (الأهم)
شُغّل R8 Full Mode على البرنامج كاملاً (النواة + الاختبارات + stubs) بابقاء نقاط دخول `main` للاختبارات فقط، ثم نُفّذت المخرجات المشوّشة نفسها:
```
ClipRepoTest: RESULT 89 passed, 0 failed
CoreTests:    RESULT 366 passed, 0 failed
PerfGate:     PERF_GATE_OK (كل البوابات العشر خضراء)
```
أي أن الإزالة والتحسين وإعادة التسمية **لا تُغيّر أي سلوك مُختبر** — وهذا أول إصدار «مُحمي» يمكن الوثوق به.

## 4. اكتشافات الأسبوع
1. **المرجع الوحيد للانعكاس في التطبيق** هو `Class.forName("java.time.Instant")` محمياً بـ try/catch في ClipIO — يُحلّ من android-30؛ لا حاجة لأي قاعدة إضافية.
2. **`R.id.copy` وغيره ظهرت في الفحص الآلي وهي `android.R.*`** (R الإطار) — استخدام R الخاص بالتطبيق حقيقي لعنصرين فقط (`dev_photo`/`dev_full`)؛ تبيّن ذلك أثناء توليد R الاصطناعي لبيئة بلا aapt2.
3. **بوابة ثابتة بوابة بلا أسنان** — أول نسخة من بوابة المكونات كانت تقارن بقائمة ثابتة؛ صارت تقرأ المانيفست نفسه، والحقن أثبتها: `.FakeGateTest` ← `R8_GATE_FAILED` وخروج 1.
4. **android.jar يخفي `java.lang.invoke`** (داخلية الإطار) — الحالة الموثوقة المعروفة التي تحل بـ `-dontwarn` لأن R8 يعيد صياغة lambdas بنفسه.
5. jar مكتبة النظام رُبط من نسخة **android-30** (نفس مستوى ربط aapt2 في المشروع) وترجمة المصادر الكاملة نجحت بلا أي استخدام لواجهات أعلى — يعني الترقية المستقبلية لـ API 35 لن تحمل مفاجآت ترجمة.
