# عقد القاموس المجتمعي — الجدول الموحد وخط المراجعة (المرحلة 2، البند D، الأسبوع 5)

**المبدأ:** ثقة المجتمع تُبنى بمدقق صارم مقاس، لا بمراجعة يدوية متفاوتة. كل دفعة اقتراحات
تصل ملف CSV واحد، تُفحص صفًا صفًا بقواعد حتمية مرتبة، وتُرفض أو تُقبل بوسم صريح، ويُكتب
تقرير مراجعة يُحفظ في أرشيف الإصدار، ويُشكر المساهمون في صفحة الإصدار بأعدادهم الحقيقية.

## 1. الجدول الموحد (إلزامي بلا استثناء)

| العمود | # | الوصف | قواعد الرفض |
|---|---|---|---|
| `word` | 1 | الكلمة سطحية **بلا تشكيل بلا تطويل** | فارغ، فيه تشكيل، ليس عربيًا (حروف 0621–064A عدا التطويل 0640 + مسافة داخلية مفردة)، أقل من حرفين أو أكثر من 40 |
| `diacritized` | 2 | نفس الكلمة مشكولة | بعد إزالة التشكيل **يجب أن تطابق `word` حرفًا-حرفًا** (يلتقط التشكيل الناقص والهيكل المكسور معًا)، وبلا أي علامة = `NO_DIACRITICS` |
| `lemma` | 3 | الجذر/الصيغة القاموسية | فارغ أو غير عربي بعد إزالة التشكيل |
| `pos` | 4 | نوع الكلمة | أحد: `noun, verb, adj, adv, particle, proper, phrase` |
| `gloss` | 5 | المعنى (سطر واحد) | أقل من حرفين، أو يحوي كلمة محظورة |
| `contributor` | 6 | اسم مستعار | نمط `[A-Za-z0-9_.\-\u0621-\u064A]{3,32}` — لا بريد ولا هوية شخصية (المبدأ الخامس) |
| `license` | 7 | الترخيص | `CC0-1.0` أو `CC-BY-4.0` فقط |

**التغليف:** UTF-8 صارم (بلا BOM — البايتات غير الصالحة ترفض الدفعة كاملة)، فواصل أسطر
`\n` أو `\r\n`، اقتباس مزدوج مع `""` للهروب، لا حقول متعددة الأسطر، سطر فارغ يُتسامح معه.

## 2. ترتيب قواعد الرفض (أول فشل يفوز — حتمي ومقاس)

`ROW_FIELDS → EMPTY_WORD → HAS_TASHKEEL_IN_WORD → NOT_ARABIC → BAD_DIACRITICS / NO_DIACRITICS → FORBIDDEN → DUPLICATE → BAD_POS → BAD_LEMMA → BAD_GLOSS → BAD_CONTRIB → BAD_LICENSE`

- **المحظور قبل المكرر** قرار مقصود أمنيًا: كلمة سامة يجب أن تُرفع بتسميتها الحقيقية
  (`FORBIDDEN`) حتى لو كانت أيضًا مكررة — لا يُسمح لأي إخفاء للسبب.
- **مكررات بفحصين:** داخل الدفعة وبعد التطبيع العربي الحساس (`Dialect.normAr`: همزات/تاء
  مربوطة/ألف مقصورة/تشكيل/تطويل — خدعة «مدرسة/مدرسه» لا تنجح)، ومقابل القاموس المثبت
  (أزواج `ar.txt` مطبّعة — 134,188 مفتاحًا وقت القياس).
- **التشكيل الجزئي مقبول:** الهيكل هو العقد، الكمال ليس شرطًا — «كِتاب» مقبولة، «كِتَار» مرفوضة.
- **رفض الدفعة الكاملة** عند `BAD_ENCODING` (BOM أو بايتات غير UTF-8) و`BAD_HEADER`
  (ترويسة ناقصة/بترتيب خاطئ): كل صفوف البيانات تحمل الوسم نفسه — جدول مكسور لا يُراجع صفًا صفًا.

## 3. الخط المقاس (ci/community_gate.sh — بوابة 17)

| الشاهد | النتيجة المقاسة |
|---|---|
| دفعة نظيفة 40 صفًا (4 مساهمين) | قبول 40/40 + تقرير JSON + CONTRIBUTORS.md |
| 9 دفعات سموم مصممة (فئة رفض لكل واحدة) | كل سم بوسمه **المتوقع حرفيًا**، والصف المرافق السليم يُقبل |
| 110 سلبيات مولدة ببذرة 1703 داخل 220 صفًا | كل مخرب مرفوض (110/110) وكل سليم مقبول |
| زمن الفحص p50 لكل صف (دفعة 800 صف) | **21µs** (السقف 5000µs) |
| القاموس المرجعي | 134,188 كلمة مطبّعة من `assets/ar.txt` |

`verdict`: `COMMUNITY_GATE_OK accepted=… rejected=… negatives=… p50_us=… batches=…`
(exit 0) أو `COMMUNITY_GATE_FAILED <سبب>` (exit 1). نقيت JVM كاملة — بلا `android.*`.

وبوابة فتح القناة (تحضير W53): `ci/communityopen_gate.sh` — تدريب مستقل بنمط W50/W51/W52-prep
يمشي القناة من وصول الدفعة إلى الحزمة الموقّعة وصفحة الشكر، ويثبت قانون الاتفاق:
مدقق الدليل (قواعد §1/§2 ميكانيكياً) والحكم المُشحن يوافقان على كل صف من كل دفعة —
لا انحراف بين الدليل والكود: `COMMUNITYOPEN_OK checks=… negatives=M/M words=… contribs=…
batches=… pack=… vc=1 vn=0.1.0`.

## 4. من الدفعة إلى صفحة الإصدار

1. يصل CSV فيسحبه `CommunityDict.review` فيتولد `Report` (معرّف الدفعة = SHA-256 للملف
   — نفس البايتات دائمًا نفس التقرير، ومراجعة لا يمكن تزييف نتيجتها لاحقًا).
2. تقرير المراجعة JSON (الإحصاءات + سجل الوسوم + المساهمون) يُحفظ في `build/community/`
   وينسخ إلى حزمة الشواهد `evidence/`.
3. **شكر المساهمين:** `Report.contributorsMd()` يولّد صفحة Markdown بأعداد المفردات
   المقبولة لكل مساهم (ترتيب تنازلي بالعدد ثم أبجدي) — المرفوضون لا يظهرون — وتُنسخ
   `CONTRIBUTORS.md` إلى `build/release/` وتُربط في قسم `community` من `release-manifest.json`.
4. ما يُدمج في القاموس المشحون لاحقًا هو الصفوف المقبولة فقط، بعد موافقة مالكة المشروع
   على تقرير المراجعة — المدقق يقترح القرار، الإنسان يوقّع عليه.

## 5. الحدود الصادقة

- قائمة المحظور محروقة في الكود (كلمات فحش شائعة + روابط/سبام) — **بداية** لا نهاية:
  التوسيع يأتي من دفعات حقيقية ويُدار كإعداد شحن، لا تعديل كود لكل كلمة.
- `gloss` لا يفحص لغويًا إلا طوله والمحظور — فحص المعنى مهمة مساهمين موثوقين أو نموذج
  لاحق، والمدقق لا يزعم فهمًا لا يملكه.
- الدمج الموقّع قائم كخطوة نشر مستقلة (`DictSign`، المرحلة 3 W2): مراجعة → بيان →
  توقيع sha256 → أصل إصدار → دبوس ذهبي → دمج المحرك بعد القاموس المثبت. ما بقي على
  المالك هو أول دفعة خارجية حقيقية تُوقَّع وتُدمج (إغلاق W53، بعد النشر) — لا تظاهر.
- `contributor` اسم مستعار اختياري الدقة: نمطه يمنع الأسماء الحقيقية المطولة، وهو غير
  مرتبط بأي حساب — لا تُجمع بيانات هوية أصلاً.

## 6. كيف تساهم — دليل المساهم (W53)

القناة مفتوحة: دفعتك ملف CSV واحد بالترويسة الموحدة (§1) — لا حساب ولا تسجيل ولا
أدوات. القواعد كلها في §1 و§2 أعلاه، وما يلي هو مسار الدفعة من يدك إلى القاموس:

1. **اكتب الملف:** ترويسة الجدول الموحد حرفياً ثم صفوفك — التشكيل الجزئي مقبول
   (الهيكل هو العقد لا الكمال)، واقتباس مزدوج للحقول التي تحوي فاصلة، ومساهمك
   اسم مستعار من دون بريد أو هوية.
2. **أرسل:** بريد إلى `cto.drs@gmail.com` بعنوان «دفعة قاموس» والملف مرفقاً — أو
   طلب دمج في المستودع يضيف الملف. العقد هو الملف نفسه لا وسيلة النقل.
3. **ما يحدث آلياً:** الفحص الحتمي صفًا صفًا بقواعد §2 (أول فشل يفوز) → تقرير
   مراجعة JSON بمعرف `SHA-256(الملف)` — نفس البايتات دائماً نفس النتيجة.
4. **التوقيع والدمج:** وقّع مالكة المشروع على التقرير (المدقق يقترح القرار، الإنسان
   يوقّع) → `DictSign` يبني الحزمة الموقّعة `neokey-dpack-1` من الصفوف المقبولة
   فقط → تُدمج بعد القاموس المثبت بسلسلة الثقة كاملة (مراجعة → بيان → توقيع →
   أصل إصدار → دبوس ذهبي → دمج المحرك).
5. **الشكر:** صفحة الشكر `CONTRIBUTORS.md` تُملأ من تقرير الدفعة الموقَّع —
   المقبولة فقط، ترتيب تنازلي بالعدد ثم أبجدي، والمرفوض لا يظهر.

**الاستجابة:** الرفض يأتي بوسمه الحرفي من §2 وكل وسم يشرح نفسه؛ والقبول يعني
مفرداتك في القاموس المشحون التالي باسمك المستعار في صفحة الشكر — لا أكثر ولا أقل.
