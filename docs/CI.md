# خط الإنتاج الآلي — CI/CD (المرحلة 0، البند B)

> المرجع في خارطة الطريق: «هجرة البناء من build.sh اليدوي المرتبط بمسارات جهاز واحد إلى خط إنتاج قياسي… الإصدار التدريجي (10% ← 50% ← 100%) يصبح إجراءً افتراضياً لا استثناءً».
> معيار الخروج من المرحلة 0: «بنية CI تعمل من دمج نظيف: اختبارات + بناء + توقيع + نشر تدريجي بلا تدخل يدوي».

## 1. المشهد الكامل

```
دمج/دفع  ──►  ci.yml (GitHub Actions)
              ├─ job gates:    ci/pipeline.sh  →  تدقيق أسرار + 455 اختباراً + بوابات أداء   (JVM خالص، بلا SDK)
              └─ job compile:  ci/build_unsigned.sh  →  aapt2 → javac → d8 → zipalign  (بلا توقيع)

وسم v*    ──►  release.yml (GitHub Actions)
              ├─ job gates:    نفس البوابات قبل توقيع أي شيء
              ├─ job release:  استرجاع الخزنة من GitHub Secrets → build.sh + build_aab.sh
              │                → رفع إلى مسار internal → إنتاج بنسبة 10%
              └─ job promote:  workflow_dispatch + اعتماد بيئة (0.5 ثم 1.0)

أي جهاز  ──►  ci/pipeline.sh      (نفس البوابات محلياً، تسجيل كامل في build/pipeline.log)
```

## 3. ملف الإصدار وخطة النشر التدريجي

`ci/release.sh` ينتج ثلاثة ملفات في `build/release/`:
- **release-manifest.json**: versionCode/Name من المانيفست (مصدر الحقيقة الوحيد)، بصمة مفتاح الرفع SHA-256 من الخزنة، حالة كل البوابات، أرقام الأداء، مسارات المخرجات.
- **rollout-plan.json / rollout-plan.txt**: المراحل 10% → 50% → 100% بشروطها: 48 ساعة مستقرة لكل مرحلة، معدل أعطال < 1%، ANR < 0.47%، بلا عنقود أعطال جديد، وإجراء الإيقاف (Play Console → Halt rollout).

## 4. الأسرار — الدائرة الكاملة

- تخزين: `.secrets/` خارج git (700/600). انظر `docs/SECURITY.md`.
- المرور إلى أدوات التوقيع عبر `env:` فقط.
- في CI: يُفكّ `ANDROID_KEYSTORE_B64` إلى نفس تخطيط الخزنة، والبصمة تُستخرج وتُطبع **وتُقارن** بما هو مسجل قبل أي رفع.
- **بوابة التغليف** `ci/package.sh` (درس الأسبوع 2: ملف تطبيق الأسبوع الثاني تضمن الخزنة الحية):
  - `neokey-app.zip` — نظيف للمشاركة، ومسح ما بعد الحزم يرفض أي `neokey.keystore` أو `.secrets/neokey.env` داخله.
  - `neokey-secrets.zip` — الخزنة وحدها بتصريح 600، للنسخ الاحتياطي المشفّر خارج الجهاز فقط.

## 5. هجرة Gradle — مُحضَّرة غير مُفعَّلة

`gradle-migration/` يلف نفس المصادر (`src/`, `res/`, `assets/`) بلا تغيير منطق، ويقرأ الإصدار من المانيفست. سبب عدم التفعيل الفوري وخطواته الثلاث: `gradle-migration/README.md`. خط CI يعمل اليوم على السلسلة اليدوية المُثبَّتة.
