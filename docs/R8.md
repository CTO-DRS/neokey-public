# R8 Full Mode — الطبقة الأولى ضد الهندسة العكسية (المرحلة 0، البند C)

> المرجع في خارطة الطريق: «تفعيل R8 بوضع Full Mode مع تشويش الأسماء وإزالة ما لم يُستخدم (حالياً يوجد D8 فقط)… الكود الحالي مكشوف للتفكيك الكامل».

## 1. ما الذي تغيّر
كان `build.sh` يستدعي **D8** فقط (تحويل class → dex بلا أي حماية: الأسماء والبنية كما هي). الآن:

- `proguard-rules.pro` — قواعد الحفظ الدنيا (انظر §3).
- `ci/build_r8.sh` — خط بناء كامل: ترجمة → **R8 Full Mode** (إزالة + تشويش + تحسين + dex في خطوة واحدة) → حزم → توقيع (بنفس انضباط الأسرار في build.sh). بدون SDK يُثبت خطوة التقليص وحدها (dex + mapping).
- `mapping.txt` يُؤرشف في `build/release/` مع كل إصدار — وهو ملف **إزالة التشويش** الذي يُرفع إلى Play Console، وبه تُقرأ آثار أعطال `last_crash.txt` بعد التشويش.
- pipeline: مرحلة `r8` صارت بوابة إجبارية، و`release.yml` يبني النسخة الموقعة على خط R8 ويرفع mapping مع AAB (`deobfuscationFile`).

## 2. النتائج المقاسة (هنا، JVM خالص + r8 8.5.35 + android-30 jar)

| المقياس | القيمة |
|---|---|
| dex بخط D8 القديم | 553,980 بايت |
| dex بخط R8 Full Mode | **420,236 بايت (-24%)** |
| أصناف البرنامج في mapping | 166 |
| مكونات المانيفست باسمها الأصلي | **8/8** (بوابة تُفشل البناء خلافاً لذلك) |
| **التحقق السلوكي**: الاختبارات 455 على المخرجات المشوّشة | **455/455 ✓ + PERF_GATE_OK** |

جرة البرنامج قبل/بعد (وضع classfile، تشمل الاختبارات): 116K ← 104K.

## 3. لماذا هذه القواعد بالذات (`proguard-rules.pro`)

| القاعدة | السبب |
|---|---|
| `-keep` للأنشطة السبعة + `NeoKeyService` مع `<init>` | النظام ينشئها بالاسم النصي من `AndroidManifest.xml` — أي إعادة تسمية = انهيار عند الإقلاع. دوال دورة الحياة تُحفظ تلقائياً (تجاوز دوال مكتبية) |
| `-keepattributes SourceFile,LineNumberTable` | تشخيص الأعطال (Perf → `last_crash.txt`) يحتاج أرقام أسطر قابلة للمطابقة مع mapping |
| `-renamesourcefileattribute SourceFile` | يخفي أسماء الملفات الحقيقية من الآثار مع بقاء الأرقام |
| `-dontwarn java.lang.invoke.**` | android.jar يخفي هذه الحزمة (داخلية في الإطار)؛ R8 يعيد صياغة lambdas بنفسه |

**ما لم نضعه عمداً**: لا `-keep` لفئات البيانات (JSON يُكتب ويُقرأ يدوياً بلا انعكاس)، لا `-dontobfuscate` (التشويش هو الهدف)، لا قواعد موارد (الموارد في APK وليست في dex). فحص الانعكاس في الكود: مرجع واحد محمي بـ try/catch (`Class.forName("java.time.Instant")`) ويُحلّ من مكتبة المنصة (android-36 منذ W130).

## 4. البوابة التي تَعَضّ
`build_r8.sh` يقرأ مكونات المانيفست فعلياً ويتحقق أن كل واحد منها **بنفس الاسم** في mapping.txt. مثبت بالحقن: إضافة `<activity android:name=".FakeGateTest"/>` بلا قاعدة حفظ →
```
R8_GATE_FAILED: manifest component com.hark.neokey.FakeGateTest was renamed/removed — add a keep rule
```
والخروج 1 يوقف الخط كله. إضافة أي مكون جديد مستقبلاً **تُجبر** المطور على قاعدة حفظ واعية.

## 5. التحقق السلوكي — كيف ثبتنا أن التقليص لا يكسر المنطق
شغّلنا R8 Full Mode على **البرنامج كاملاً** (النواة + الاختبارات + الـ stubs) بنقاط دخول `main` للاختبارات فقط، ثم نفّذنا المخرجات المشوّشة: `ClipRepoTest` (89) + `CoreTests` (366) + `PerfGate` — كلها خضراء. يعني: الإزالة والتحسين وإعادة التسمية لا تغيّر سلوكاً مُختبراً.

## 8. التقليم الحقيقي (المرحلة 4، الأسبوع 22) — الأحرف تسكن الموارد

الوعد الموثق مرتين («التقليم الحقيقي لا رفع») نُفذ أخيراً: 119 نصاً عربياً
ثابتاً كبيراً (≥60 بايت، 15,008B محتوى خاماً) هُجّرت بايت-لطرفاً من أصناف
الواجهة السبعة (SetupActivity/ClipIOActivity/WriterActivity/PerfActivity/
BackupActivity/DictActivity/NeoKeyService) إلى `res/values/strings.xml` —
الموارد تسكن الـ APK عبر aapt2 لا الـ dex. القياس: **518,688 → 504,476B
(−14,212B)**، والسقف **خُفِّض** 520,000 → **512,000** في `ci/build_r8.sh`
(هامش 7,524B ≈ 5.7× هامش الأسبوع 20). ما بقي في الكود عمداً: بادئات static
(لا Context فيها)، وسلاسل البروتوكول (SQL/روابط/تعليمات المساعد الإنجليزية).
المبادئ التي لم تُمس: الفئات النقية (صفر android.*) لا تستورد الموارد إطلاقاً
— جودة النص العربي بايت-لطرفاً (تحقق round-trip آلي: فك تهريب Java = فك
تهريب aapt2 لكل نص قبل الكتابة).

الحراسة الدائمة: `ci/trim_gate.sh` → `TrimGate.java` (مرحلة `trim` بعد `r8`):
سقف 512,000 + أدنى من 518,688، تقاطع src ↔ strings.xml (لا ميت ولا ناقص ولا
مكرر)، QC لكل مدخل، صفر نص عربي طويل يعود لأصناف الواجهة، النقاء (كل
`import android` في مجموعة run.sh له stub)، واقتران `ui_en.txt` (80 مفتاحاً
يتطابق حرفياً — الترجمة الإنجليزية تعمل كما هي). كما صار مولّد الـ R الوهمي
في مسار الإثبات offline **يُشتق آلياً من strings.xml** فلا يمكن أن ينحرف.


## 9. أدوات الأرتقف الموقَّع (المرحلة 6، الأسبوع 31)

مسار الإصدار الموقَّع الكامل يعمل بلا SDK كامل — ثلاثة تنزيلات فقط إلى `tools/`:

```bash
# aapt2 (ثنائي Linux مستقل — يربط الموارد ويولد R الحقيقي):
curl -sSfL -o tools/aapt2-pkg.jar https://dl.google.com/android/maven2/com/android/tools/build/aapt2/9.5.1-16666295/aapt2-9.5.1-16666295-linux.jar
unzip -oj tools/aapt2-pkg.jar aapt2 -d tools/ && chmod +x tools/aapt2

# apksig (التوقيع v1+v2 والتحقق — مكتبة Google الرسمية نفسها التي يستخدمها AGP):
curl -sSfL -o tools/apksig.jar https://dl.google.com/android/maven2/com/android/tools/build/apksig/9.5.1/apksig-9.5.1.jar

# android.jar (منصة 36 — يفك إلى android-36/):
curl -sSfL -o /tmp/platform-36.zip https://dl.google.com/android/repository/platform-36_r02.zip
unzip -oq /tmp/platform-36.zip -d /tmp/p36 && cp /tmp/p36/android-36/android.jar tools/android.jar
```

الأمران (بلا أسرار ثم بالمخزن — التفصيل: `docs/PHASE6-W2-REPORT.md`):
```bash
ci/build_signedapk.sh   # aapt2 link + align (dex الأنبوب + arsc STORED/4B) → build/sapk/aligned.apk
java -cp build/signedapk-gate:tools/apksig.jar com.hark.neokey.SignedApk sign \
  build/sapk/aligned.apk build/NeoKey-2036.apk <ks> <pass> <alias> <البصمة المنشورة>
```

منذ هذا الأسبوع يبني `ci/build_r8.sh` الـ dex ضد **الـ R الحقيقي** عند توفر
aapt2 (معرفات 0x7f… — dex الـ stub بثوابت 1..N كان سيحل الموارد خطأ وقت
التشغيل؛ 120 إحالة `R.*` مباشرة في الكود)، ويبقى مسار الـ stub احتياطاً
لبيئات بلا aapt2 — dex الـ stub لا يُشحن في أرتقف أبداً. القياس: 505,264 →
505,636B (Δ+372) تحت سقف 512,000.
