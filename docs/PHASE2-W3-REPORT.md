## 1. ما أُسلّم

البند B من خارطة المرحلة 2 — تشغيل صيغة `.neokey` الموجودة أصلاً كخط إنتاج
مقاس، لا كوصف:

|---|---|---|
| مدقّق الحزم الآلي | `src/com/hark/neokey/ThemePack.java` (نقي JVM، صفر `android.*`) | المراجعة الآلية: JSON صارم + قائمة مفاتيح + جودة عربية + تباين + نطاقات + دبوس نشر |
| اقتصاد 70/30 | `src/com/hark/neokey/Economy.java` (نقي JVM) | تقسيم بالسنتات، دفتر شهري، استرداد وتعديلات، حد أدنى، دفعة idempotent |

## 2. الأرقام المقاسة (بوابة `THEME_STORE_GATE_OK` — 112 فحصاً، 0 إخفاق)

- **الكتالوج:** 10 مؤسسين، 25 حزمة (22,499 بايت كتالوج) — **25/25 تمرّ** المراجعة
  الآلية، و`sha256` لكل حزمة مطابق لدبوس الكتالوج (البايتات المراجَعة =
  البايتات المنشورة).
- **زمن المراجعة الآلية:** p50 **0.096 ms**، p95 0.143 ms (الحد < 5 ms — هامش
  ~52×). المراجعة الكاملة لكتالوج الإطلاق أقل من 3 ms مجتمعة.
- **السلبيات المصممة:** **23 حزمة ضارة رُفضت كلها بالوسم الصحيح** — مفتاح API
  مزروع (`key:api_key`)، رابط تسريب (`key:webhook_url`)، حقول تتبع، حزمة 65KB+،
  مورد غير معلن/مفقود، محارف اتجاه/تشكيل/تطويل/طول في الاسم، نص مطابق
  للسطح (`contrast.key`)، حدود `font/anim/borderW`، إساءة `layout`، هوية تطبيق
  مغلوطة، ألوان ناقصة/فاسدة، مفتاح JSON مكرر، لاحقة زائدة، محرف تحكم خام،
  نيون بلا توهج.
- **عبث ما بعد المراجعة:** قلب بايت واحد بعد القبول (لا يزال يمرّ بالمراجعة
  لصلاحية hex الجديد) → **الدبوس يرفضه**. النشر مثبَّت بالتجزئة لا بالثقة.
- **الاقتصاد على شهر كامل محاكى** (420 عملية بيع + استردادات، seed حتمي):
  إجمالي 125,080 سنتاً، استردادات 5,633، نصيب المبدعين **83,609 (70.00%)**
  والمنصة **35,838 (30.00%)** — الدفتر ينغلق سنتاً بسنت
  (`Σcreator + platform == gross − refunds`)، التقسيم دقيق على أسعار
  الكتالوج كلها (149→104/45، 499→349/150، 1→0/1)، استرداد يفوق إجمالي بائع
  يمتصه ويُبلَّغ عنه دون لمس غيره، حد الأدنى ($10 على نصيب المبدع) يحمل
  للشهر التالي، والدفعة idempotent.
- **الحزمة الكاملة:** `PIPELINE_OK` 15 مرحلة، اختبارات **923/923** (+80).

## 3. الإثبات السلبي للبوابة (إلزامي)

إخفاء `src/com/hark/neokey/ThemePack.java` → `THEME_STORE_GATE_FAILED compile`
**exit 1** → استعادة الملف → `THEME_STORE_GATE OK` مجدداً. البوابة تقيس
الوحدة، لا وجودها.

## 4. القرارات الهندسية

1. **المتجر صارم والعميل متسامح.** `Theme.fromSpec` يُقحم النطاقات ويشتق
   الألوان الناقصة — جيد للاستيراد المحلي، خطر على منصة تنشر باسمها. المتجر
   يرفض ما يتسامح معه العميل (`range.*` على نفس حدود fromSpec و`docs/STORE.md`).
2. **قائمة المفاتيح المسموحة هي حاجز المفاتيح المزروعة.** الحزمة JSON بيانات
   وصفية فقط؛ أي مفتاح خارج القائمة (api_key/webhook/tracking) رفض فوري حتى
   لو كانت السمة سليمة — التهريب يُقطع عند الشكل لا عند السلوك.
3. **التباين مقاس على المركّب.** المفاتيح الزجاجية شفافة؛ نسبة WCAG تُحسب بعد
   دمج الشفافية فوق الخلفية — والقاعدة نفسها مثبتة في مولّد الكتالوج (Python)
   والبوابة (Java) بنفس الرياضيات.
4. **جودة الاسم العربي قاعدة نشر لا ذوق:** لا تشكيل في أسماء السمات (نص منتج)،
   لا تطويل، لا محارف اتجاه (تجاوز bidi يفسد العرض في القوائم)، و40 محرفاً
   كحدّ للعرض الواجهي.
5. **اقتصاد بلا فاصلة عائمة:** كل المال `long` سنتات؛ التقسيم floor للمبدع
   والباقي للمنصة فيجب المجموع دائماً؛ الترتيب حتمي بمعرّف المبدع.

## 5. دروس البيئة المقاسة

- **فقدان JDK و`tools/android.jar` و`tools/r8.jar`** مع إعادة تدوير بيئة
  التنفيذ: بوابات JVM صمّمت أصلاً مع ECJ فبقيت تعمل، لكن `sync_client_gate`
  كانت تعتمد على `android.jar` لترجمة `Dictionary` (واجهة `Context`) — أُضيف
  مسار السقوط إلى **stubs الاختبارات المعتمدة نفسها** (`tests/stubs/android/**`)
  التي تستخدمها `run.sh` كل أسبوع: أنواع ترجمة فقط، والسلوك يبقى من الأصناف
  النقية تحت الاختبار. العقد موثق داخل السكربت.
- عدد الاختبارات في العدّاد الخطي كان يقرأ صيغة `RESULT n passed, m failed` —
  المجموعتان الجديدتان طبقتا الاصطلاح نفسه.
- **dex:** بلا تغيير عن قياس الأسبوع 14 (499,984B عند آخر تشغيل R8 على جهاز
  البناء) — `ThemePack`/`Economy` غير قابلتين للوصول من أي مسار manifest فيُقلّمهما
  R8 (النمط نفسه المثبت في المرحلة 1 عند A1/C1)، وكلفتهما صفر بايت حتى أسبوع
  واجهة المتجر. بوابة R8 تخطت هنا لفقدان الأدوات — تُقاس حيث توجد.

## 6. ما لم يُسلَّم (مقيد لا منسي)

- واجهة متجر داخل التطبيق (تصفح/شراء) — الأسبوع القادم داخل البند C أو بعده
  حسب الخطة؛ الخط الحالي هو ما تستهلكه تلك الواجهة.
- مدقق بيئي يدوي للسمات (لقطات شاشة) — خط المراجعة الآلي يعطي حكم القبول،
  واليدوي يتلقى قائمة مرتبة.
- خادم متجر حيّ ودفعات حقيقية — المحاكاة والقياس هنا، والنشر قرار تشغيل
  (نفس فصل العقد المطبق في المزامنة، `docs/SYNC-REST.md`).

ذهبية بت-لطرف + مواصفة Swift).
