# 02 — خطوات المطور القادمة (قائمة تنفيذية بترتيب لا يُخترق)

> **إضافة تنفيذية** تُلخص وتُنظّم ما في `README-HANDOVER.md` §4 و`recovery/RECOVERY-INSTRUCTIONS.md` في شكل قائمة شطب. كل أمر جاهز للنسخ. **لا تنتقل لخطوة قبل إغلاق سابقتها** — السكربتات نفسها تتوقف عمداً عند أي فشل، فافعل مثلها.

---

## ☐ 0. الأمن أولاً (قبل توصيل أي جهاز للمستودع)

```bash
# اسحب من GitHub فوراً (إعدادات → Developer settings → Tokens):
#   كل توكن قديم، وبخاصة التوكن الذي يبدأ بـ ghp_••••…  (ظهر مكشوفاً في سجل محادثة)
```
- [ ] التوكن القديم `ghp_••••…` مسحوب (منقول = صفر صلاحية)
- [ ] أنت تعلم أن هذا المشروع يحمل مفتاح توقيع التطبيق مدموجاً في `.secrets/` (الجذر) — **لا ترفع الحزمة لأي مكان عام، ولا المفتاح إلى git أبداً** (مستثنى في `.gitignore`)

## ☐ 1. أنشئ توكناً جديداً قصير العمر

- النوع: **Fine-grained** على `CTO-DRS/neokey-hark` فقط
- الصلاحية: `Contents: Read` (أضف `Write` فقط إن كنت ستدفع)
- المدة: قصيرة (7 أيام مثلًا) — **يُسحب بعد انتهاء الاستعادة بغض النظر عن النتيجة**

```bash
umask 077
printf '%s' 'ضع_التوكن_هنا' > /tmp/gh.token
chmod 600 /tmp/gh.token
```

## ☐ 2. جهّز البيئة

- Linux + `git` + `bash` + `python3` + JDK
- ⚠️ **لا تثبّت أدوات البناء السبع يدوياً** (r8، android.jar، apksig، sqlite-jdbc، slf4j، ecj، aapt2) — سكربت `scripts/fetch_tools.sh` داخل المستودع يثبتها بشفرات sha256 ويرفض أي انحراف. لا يوجد هذا السكربت في الحزمة — هو داخل المستودع بعد الاستنساخ.
- لا تثبت شيئاً آخر قبل قراءة `ci/pipeline.sh`.

## ☐ 3. شغّل الاستعادة (القناة الوحيدة المشروعة للأسابيع 22–45)

```bash
bash recovery/restore-from-github.sh
```

ما يجب أن تراه بالترتيب، ورموز الفشل التي تقف عندها عمداً:

| رمز النجاح | المعنى | رمز الفشل المقابل |
|---|---|---|
| `OK-2` | التوكن يصل للمستودع الخاص | `FAIL-1/1b/2` |
| `OK-3` | استنساخ نظيف + آخر 5 commits | `FAIL-3` |
| `OK-4` | **الارتكاز `23dbc0a` في التاريخ** — إلا توقف السكربت | `FAIL-4` → **توقف فوراً ولا تثق بالاستنساخ** |
| `--- inventory ---` | جرد صريح لما يوفره المستودع وما ينقصه | — |
| `OK-6a` | الأدوات السبع تحقق بشفراتها 7/7 | `FAIL-6a` → لا تكمل |
| `OK-6b` | **`PIPELINE_OK`** — الضوء الأخضر الوحيد | `FAIL-6b` → اقرأ آخر خطأ؛ لا إصلاح يدوي عشوائي |

- [ ] وصلت إلى `RESTORE COMPLETE` — لا تعلن أي جاهزية قبل هذا السطر
- [ ] **اسحب التوكن الآن** (استُخدم في جلسة — التدوير بند في التعليمات نفسها)

## ☐ 4. حدّد موقعك على الخارطة (لا تخمّن)

```bash
git log --oneline -15                 # أين يقف التاريخ فعلاً؟
tail -40 HISTORY.md                   # آخر ما وُثّق بالأرقام
ls docs/ | grep PHASE9                # هل خطة المرحلة 9 مكتوبة؟
grep -A20 pendings docs/PHASE8-W4-REPORT.md   # مصدر اشتقاق الخطة القادمة
```

قارن ما تراه مع `01-ROADMAP-CLARIFIED.md` §6 — أي اختلاف بين الواقع والوثائق، **الواقع هو المرجع**، ووثّق الفرق في تقرير.

## ☐ 5. أول التزام عملي: نشر W45 المعلق

آخر نشاط موثق في سجل المشروع: نشر W45 كان **قيد التنفيذ** (تصحيح بايتات + `PHASE9_OK` + إثبات أخضر + proof commit) ولم يُؤكد اكتماله.

- [ ] تحقق: هل اكتمل؟ (ابحث عن proof commit الخاص به + سجل `PHASE9_OK` + بيان الإصدار)
- [ ] إن كان معلقاً: أكمله **بنفس طريقة المشروع** — بوابة ← إثبات إيجابي ← إثبات سلبي ← أرشفة ← proof commit. لا تختصر.

## ☐ 6. اشتق خطة باقي المرحلة 9 واعمل

- [ ] اشتق بنود العمل من `pendings` في `docs/PHASE8-W4-REPORT.md` (وإن وجدت `docs/PHASE9-PLAN.md` فابدأ منها) — **لا تبتكر بنوداً خارج الاشتقاق** (القاعدة الذهبية)
- [ ] كل أسبوع جديد = تزايد مثبت: بوابة قاسرة + اختبارات خضراء + **إثبات سلبي** + تقرير + حزمة + proof commit
- [ ] راقب سقف dex (كان 512,000 عند W39) وراقب `versionCode` (الإصدار الجديد يبدأ من **vc83** فما فوق — لا تنزل أبداً)

## معيار قبول التسليم (Definition of Done)

التسليم يُعتبر مقبولاً عندما تتحقق الأربعة معاً:

1. `OK-4`: الارتكاز `23dbc0a` موجود في تاريخ الاستنساخ.
2. `OK-6a` + `OK-6b`: الأدوات 7/7 والأنبوب يطبع `PIPELINE_OK`.
3. حالة W45 محسومة موثقاً (مكتمل أو مُكمل بوثائقته).
4. نقطة استعادة جديدة مثبتة خارج بيئة العمل.

أي بند آخر — مهما بدا مهماً — يأتي **بعد** هذه الأربعة.

## قواعد الاشتباك مع الشيفرة (تذكير)

- الضوء الأخضر الوحيد: `PIPELINE_OK` من `ci/pipeline.sh`.
- كل بوابة جديدة تُولد معها إثباتاً سلبياً في نفس اليوم، وإلا فهي ليست بوابة.
- الأرقام تُقاس ولا تُقدّر: كل ادعاء في تقرير مقابل له سطر قياس.
- ما لا يمكن قياسه في بيئتك (خوادم حية، دفع حقيقي، متجر) يُبنى نواته القابلة للقياس ويُوثق عقد التسليم — كما فعلت المراحل 1–3.
- عند الشك: اقرأ `HISTORY.md` و`CI.md` داخل اللقطة، ثم اسأل السجل لا الذاكرة.
