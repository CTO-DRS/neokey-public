# تعليمات الاستعادة من GitHub — مشروع NeoKey

هذا السكربت هو **القناة الوحيدة المشروعة** لاستعادة حالة المشروع من الأسابيع 22 وما بعد.
سكربت الاستعادة: `restore-from-github.sh` (مرفق بجوار هذا الملف، ومُختبر الدخول والسلوك).

## المتطلبات
1. توكن GitHub جديد وصالح على المستودع الخاص `CTO-DRS/neokey-hark`:
   - النوع الموصى به: Fine-grained token، الصلاحية `Contents: Read` (أضف `Write` فقط إذا ستحتاج للدفع).
   - مدة قصيرة (7 أيام مثلًا) ثم سحبه بعد انتهاء الاستعادة.
2. `git` و `bash` على جهاز Linux.

## الخطوات (بالترتيب، بلا تخطي)
```bash
# 1) الأمن أولًا: اسحب أي توكن قديم ظهر في محادثات أو سجلات (القديم يبدأ بـ ghp_••••…).

# 2) اكتب التوكن الجديد في ملف مؤقت بصلاحيات صارمة:
umask 077
printf '%s' 'ضع_التوكن_هنا' > /tmp/gh.token
chmod 600 /tmp/gh.token

# 3) شغّل الاستعادة:
bash restore-from-github.sh
```

## ما الذي يجب أن تراه عند النجاح (بالترتيب)
| الرمز | المعنى |
|---|---|
| `OK-2` | التوكن يمنح الوصول للمستودع الخاص |
| `OK-3` | استنساخ نظيف + عرض آخر 5 commits |
| `OK-4` | الارتكاز `23dbc0a` (W41 / vc82 / v3.5 / إغلاق Phase 8) موجود في تاريخ الفرع — وإلا يتوقف السكربت بنفسه |
| `--- inventory ---` | جرد صريح لما يوفره المستودع وما ينقصه (pipeline، fetch_tools، keystore، secrets، تقارير المراحل) |
| `OK-6a` | الأدوات السبع المثبتة بشفرات sha256 تحقق بنجاح (عبر `scripts/fetch_tools.sh` داخل المستودع) |
| `OK-6b` | `PIPELINE_OK` من `ci/pipeline.sh` — **الضوء الأخضر الوحيد** |

عند `RESTORE COMPLETE` فقط يُعلن أن الحالة استُعادت. أي شيء آخر = غير مستعاد.

## معاني الفشل (يفشل السكربت مغلقًا — لا يكمل أبدًا على شك)
- `FAIL-1` لا يوجد توكن في `/tmp/gh.token` → أعد الخطوة 2.
- `FAIL-1b` صيغة التوكن غير متوقعة → تأكد أنك نسخت التوكن كاملًا بلا أسطر زائدة.
- `FAIL-2` التوكن لا يصل للمستودع → راجع صلاحيات التوكن أو انتهت صلاحيته أو سُحب.
- `FAIL-3` فشل الاستنساخ → مشكلة شبكة أو صلاحيات.
- `FAIL-4` الارتكاز `23dbc0a` ليس في التاريخ → **توقف فورًا ولا تثق بهذا الاستنساخ**؛ المستودع الخطأ أو قُصّ تاريخه.
- `FAIL-6a` شفرات الأدوات لم تتحقق → لا تكمل، الأدوات ليست التي ينتظرها المشروع.
- `FAIL-6b` الأنبوب لم يصل `PIPELINE_OK` → اقرأ آخر خطأ في مخرجات الأنبوب؛ هذا التزام مشروع، لا إصلاح يدوي عشوائي.

## بند الأسرار والتوقيع
- المستودع عادة **لا يحمل** `neokey.keystore` ولا `.secrets/`.
- حزمة التسليم تحتوي `weeks/NeoKey-Week17/neokey-secrets-week17.zip` (نفس مفتاح التوقيع الثابت منذ أسبوع 15: `.secrets/neokey.keystore` + `.secrets/neokey.env`).
- إن طلب الأنبوب التوقيع وفقرده المفتاح: فك ضغط أرشيف الأسرار إلى جذر المستودع (`unzip weeks/NeoKey-Week17/neokey-secrets-week17.zip -d <جذر-المستودع>`).
- ⚠️ أرشيف الأسرار هذا من عهدة أسابيع 15–17؛ تحقق بعد الاستنساخ أن الأنبوب لا يطلب مفتاحًا أحدث، ولا تدفع الأسرار إلى git أبدًا.
